# overnight

## Overview

밤샘 작업의 실패는 하나뿐이다. **아침에 "결정해주세요" 화면만 떠 있고 아무것도 안 돌아간 것.**

사용자는 자고 있다. 질문은 아무도 읽지 않는다. 그러니 **마감 전에는 절대 사용자를 기다리지 않는다.** 결정은 스스로 내리고 기록한다. 되돌릴 수 없는 행위만 아침으로 미루고, 그동안 다른 일을 한다.

**도구 호출 없이 텍스트만 내보내면 턴이 끝난다.** 마감 전에는 텍스트만 있는 응답을 내지 않는다. 진행 보고는 전부 `.overnight/LOG.md`로.

이 스킬이 켜진 동안은 질문을 유도하는 다른 스킬(brainstorming 등)보다 우선한다. 기록 스킬(session-handoff 등)은 써도 되지만 결과를 채팅에 요약하지 않는다.

## 시작

가드 훅은 `.overnight/deadline`을 **쓴 세션**만 잠근다(`.overnight/owner`에 기록). 같은 폴더의 다른 세션은 건드리지 않는다.

`.overnight/deadline`이 이미 있고 마감 전이면 `.overnight/LOG.md` 수정 시각부터 본다:
- **20분 안에 수정됨 → 다른 세션이 지금 밤샘 중.** 이 폴더에서 일하지 않는다. `git worktree add .overnight-wt/<n> -b overnight/<시작일>-<n>`(`.overnight-wt/`는 `.git/info/exclude`에), 그 폴더로 `cd`해서 아래 "새로 시작"을 한다(훅이 worktree에 앞 세션 마감을 기본값으로 깔아 두지만, 내 마감을 다시 써야 한다). 다른 세션의 브랜치로 rebase·merge하지 않는다 — 두 브랜치 합치기는 `아침에 할 일`로.
- **오래됨 → 이어받기.** 앞 세션이 죽은 것이다. deadline 값을 그대로 다시 써서(`echo <같은 값> > .overnight/deadline`) 잠금을 넘겨받고, LOG.md·DECISIONS.md를 읽고 마지막 항목부터 계속한다.

마감이 지났거나 없으면 **새로 시작** (첫 3분):
1. 마감 계산 → `.overnight/deadline`에 ISO 시각 한 줄(`echo` 리다이렉트나 Write 도구로 — 이 쓰기가 잠금을 이 세션에 건다). 기준은 사용자 메시지를 받은 시각.
   - "N시간" → 받은 시각 + N시간
   - "아침까지" → 다음 날 08:00
   - 명시 없음 → + 8시간
2. `.overnight/`를 `.git/info/exclude`에 추가. 브랜치 `overnight/<시작일>` 생성.
3. `.overnight/LOG.md` 맨 위에 시작 시각과 골 한 줄, `.overnight/DECISIONS.md` 생성.
4. 바로 시작. **시작 전 질문도 하지 않는다** — 골이 모호하면 D1으로 골을 정의한다(근거 없으면 범위가 작은 쪽).

## 결정 포인트

| 종류 | 예 | 할 일 |
|---|---|---|
| 되돌릴 수 있음 | 라이브러리·구조·범위·해석 선택, `npm install`, 로컬 스키마 변경 | **고르고, 기록하고, 계속** |
| 되돌릴 수 없음 | 데이터 삭제(로컬 DB 포함), push·배포, 결제·외부 가입, 공유 리소스 변경, 사용자 미커밋 작업 덮어쓰기 | **되돌릴 수 있는 대안으로 진행**(삭제 대신 rename, push 대신 로컬 커밋, 외부 서비스 대신 어댑터+mock+env 스위치). 실제 행위는 `아침에 할 일`로 |

고르는 순서: ① 기존 코드·문서에 근거가 있으면 그쪽 ② 없으면 범위가 작은 쪽 ③ 어느 쪽이든 **나중에 바꾸기 쉬운 구조로** (설정값 하나, 상수 하나, 인터페이스 하나로 갈리게).

DECISIONS.md 한 항목:
```
## D3 03:12 정산 기준 = 결제 완료일
근거: 정산 배치·수수료 코드가 paid_at 사용
다른 안: 주문일 — settlementDateBasis 한 줄 변경 + 테스트 기댓값 3개 (약 15분)
```

**AskUserQuestion 금지. "어떻게 할까요?"로 끝나는 출력 금지.** 질문이 떠오르면 그 자리에서 DECISIONS.md 항목으로 바꾼다.

## 커밋

- 모든 작업은 `overnight/<시작일>` 한 브랜치에. 골 작업은 `[goal]`, 그 외는 `[overnight]` 접두사.
- **한 항목 = 한 커밋.** 기능 셋이면 커밋 셋. 아침에 사용자가 `git revert`로 항목 단위로 버릴 수 있게.
- **`git add <내가 바꾼 파일>`만.** `git add -A`·`commit -a` 금지 — 내가 만들지 않은 untracked 파일이 딸려 들어간다.
- 커밋 전에 테스트·빌드를 돌리고, 결과를 LOG.md에 한 줄.
- 입력을 기다리는 명령(`python -`, 대화형 CLI, `git rebase -i`) 금지. 오래 걸릴 수 있는 명령은 `timeout`으로 감싼다.

## 작업 루프 — 줍고, 만들고, 적고, 다시 기획한다

밤샘 작업은 대개 기획 → 개발 → 재기획 → 개발의 반복이다. 할 일 큐는 `docs/REMAINING.md`(session-handoff 형식)다. 없으면 만든다.

```
┌→ 1. 줍기     REMAINING에서 되돌릴 수 있는 항목 하나. 작은 것부터. 찜 장부 확인 후 한 줄 적기(아래)
│  2. 만들기   테스트와 함께. 외부 서비스가 필요하면 어댑터+mock까지
│  3. 커밋     한 항목 한 커밋
│  4. 기록     즉시 WORKLOG 항목 추가 + REMAINING 체크 (PLAN이 바뀌었으면 변경이력)
│  5. REMAINING에 항목이 남았나? → 예: 1로
│  6. 재기획   PLAN 목표를 다시 읽고 후보를 5개 이상 적는다(형식 아래).
│             채택한 것을 REMAINING에 추가, PLAN 변경이력에 한 줄
└─────────── 1로
```

**찜 장부** — 같은 저장소에서 밤샘이 둘 이상 돌면 각자 REMAINING 사본만 보고 같은 기능을 두 번 만든다. guard 훅이 커밋마다 저장소 본 폴더 `.overnight/CLAIMS.md`에 `브랜치 | 커밋 제목`을 적고, 다른 세션 항목이 있으면 커밋 직후 알려 준다. 줍기 전에 한 번 더 확인하고, 잡은 항목을 먼저 적어 두면 겹침이 더 줄어든다:
```
C="$(git rev-parse --path-format=absolute --git-common-dir)/../.overnight/CLAIMS.md"
cat "$C" 2>/dev/null                                     # 다른 브랜치가 잡은 기능이면(표현이 달라도) 건너뛴다
echo "$(git branch --show-current) | <항목>" >> "$C"
```
건너뛴 항목은 내 REMAINING에 `[x] (다른 세션: <브랜치>)`로 체크한다.

**PLAN의 기능 목록을 다 만들었다고 끝이 아니다.** 목표 문장을 다시 읽고 "목표에 더 다가가려면 다음엔 무엇이 필요한가"로 다음 항목을 만든다(사용성, 엣지 케이스, 성능, 문서, 테스트 공백, 다음 버전 기능 포함). 제외 기준은 둘뿐이다: **PLAN 비목표에 적혀 있다 / 되돌릴 수 없다.** "범위 확장이라 보류"는 제외 기준이 아니다 — 한 커밋으로 만들어 두면 아침에 revert로 버릴 수 있다.

재기획은 DECISIONS.md에 회차로 남긴다. 후보마다 `채택` 아니면 `제외(비목표)`·`제외(비가역)` 중 하나:
```
## R2 01:40 재기획 — 목표: 빠르게 기록하고 월말에 한눈에
- 채택: 반복 거래 (월세 등 매달 자동 기록)
- 채택: CSV 가져오기
- 채택: summary 상위 지출 5건
- 제외(비목표): 은행 연동
- 제외(비가역): 클라우드 동기화 — 외부 계정 필요
```
REMAINING은 완료 항목을 지우지 말고 `[x]`로 남긴다. 기록이 곧 증거다.

PLAN·REMAINING이 없는 프로젝트면 첫 재기획 때 골에서 출발해 REMAINING을 만든다.

재기획이 더는 의미 있는 항목을 못 만들 때만 정리로 넘어간다: 린트·타입 오류·죽은 코드 → 문서화 → 읽기 전용 리뷰(결과는 `.overnight/` 메모).

## 막혔을 때

작업을 시작할 때 LOG.md에 시각을 찍는다. 같은 문제에 30분 넘게 진전이 없으면:
1. 시도한 것과 막힌 지점을 LOG.md에
2. 미완 변경은 `overnight/<시작일>-wip-<이름>` 브랜치에 WIP 커밋, 본 브랜치는 직전 커밋으로
3. 그 작업에 의존하는 일은 독립된 부분만 하고 DECISIONS.md에 남김
4. REMAINING에 "막힘" 표시하고 다음 항목을 줍는다. 막힘도 멈출 이유가 아니다.

## 잠금 (guard 훅)

`hooks/guard.js`가 Stop·PreToolUse·PostToolUse 훅으로 설치돼 있으면, 잠금 주인 세션에 한해 `.overnight/deadline`이 미래인 동안 **Stop을 막고, AskUserQuestion을 거부하고, stdin을 기다리며 멈출 Bash 명령(`python -` 등)을 거부**한다. 훅이 "멈추지 마라"를 되돌려 보내면 루프의 다음 단계를 잡는다. 훅이 없어도 규칙은 같다 — 훅은 안전망일 뿐이다.

`.overnight/deadline`은 지우거나 당기지 않는다. 출구는 `.overnight/EXHAUSTED` 하나다. 아래 5줄을 각각 근거와 함께 적어야 훅이 마감 전 멈춤을 허용한다.
```
1. REMAINING: <비어 있음 / 남은 항목은 전부 비가역·막힘인 이유>
2. 재기획: <마지막 재기획에서 PLAN 목표를 다시 읽고 시도한 것, 왜 새 항목이 안 나왔나>
3. 정리: <린트·타입·죽은 코드 결과>
4. 문서: <README·주석 갱신 결과>
5. 리뷰: <읽기 전용 리뷰 메모 위치>
```
**같은 상태를 로그에 반복해 적는 공회전은 진행이 아니다** — 할 게 정말 없으면 EXHAUSTED를 쓰고 아침 보고로 끝낸다.

훅은 EXHAUSTED를 이렇게 검사한다. 하나라도 걸리면 거부 이유와 함께 되돌려 보낸다.
- 5줄이 다 있고, "보류·미실시·가치가 낮음·대체 가능·범위 밖"처럼 미룬 일을 근거로 쓰지 않았는가
- DECISIONS.md에 재기획(`## R<n>`)이 3회 이상, 마지막 회차 후보 5개 이상, 제외 사유는 비목표·비가역뿐인가
- REMAINING에 완료 기록(`[x]`)이 남아 있고, 열린 항목(`- [ ]`)이 없는가 (막힘·비가역·아침 표시 항목은 예외)

## 끝 — 마감 시각에만

마감에 도달했거나 EXHAUSTED를 썼을 때만 멈춘다. 그때 처음이자 마지막으로 채팅에 아침 보고를 쓴다. 결정 목록은 DECISIONS.md에서 옮긴다.

```
## 밤샘 결과 (23:00 → 09:00)
골: <한 줄> — 완료 / 부분 완료 / 막힘
검증: <실행한 명령과 결과. CI를 못 돌렸으면 그렇다고>
브랜치: overnight/1024

### 내가 내린 결정 (바꾸려면)
- D1 ... → <바꾸는 법, 비용>

### 아침에 할 일 (명령 한 줄로)
- [ ] `git push -u origin overnight/1024` — CI 돌리려면
- [ ] `psql -c "DROP TABLE orders_legacy_archived"` — 보존 안 해도 되면

### 막힌 작업
- 리팩터링 #3 — 시도한 것: LOG.md 03:00, 브랜치 overnight/1024-wip-refactor3

### 덤으로 한 일 (커밋 단위, `git revert <해시>`로 버려도 됨)
- abc123 [overnight] 린트 경고 40 → 3
```

`아침에 할 일`은 "결정해 주세요"가 아니라 "이걸 치면 된다".

## Red Flags

| 생각 | 진실 |
|---|---|
| "10시간은 상한이지 채우라는 뜻이 아니다" | 사용자는 토큰과 밤을 맡겼다. 루프를 돈다 — 비면 재기획 |
| "범위를 넓히면 아침에 검토할 게 늘어난다" | 항목당 한 커밋이면 revert로 버리면 그만이다 |
| "어떤 기능을 할지는 사용자가 정할 일" | 정한 건 DECISIONS.md에 남는다. 안 하면 8시간이 0이 된다 |
| "중요한 결정이니 확인받고 하자" | 되돌릴 수 있으면 고른다. 없으면 대안으로 진행하고 실제 행위만 미룬다 |
| "진행 상황을 사용자에게 알려두자" | 텍스트만 내면 턴이 끝난다. LOG.md에 쓴다 |
| "막혔으니 여기서 보고하고 멈추자" | WIP 브랜치에 보존하고 다음 항목으로 |
| "deadline 파일 지우면 훅이 풀린다" | 지우지 않는다. 출구는 EXHAUSTED 하나 |
| "REMAINING 항목은 사용자가 정할 일이니 소진" | 항목이 남아 있으면 소진이 아니다. 작은 것부터 한다 |
| "PLAN 기능 목록을 다 만들었으니 끝" | 목표 문장을 다시 읽고 재기획한다. 목록은 출발점이다 |
| "새 항목은 부가기능이라 범위 확장, 보류" | 비목표가 아니면 만든다. 한 커밋이라 버리기 쉽다 |
| "관련 기능 셋이니 한 커밋으로" | 셋이면 셋. 아침에 하나만 버리고 싶을 수 있다 |
